# Helm

**Helm keeps your stablecoins earning under limits you set once: a neural network proposes the split every cycle, and a reactive contract clamps every proposal to your limits on-chain.**

Yield optimisers chase today's best rate and are wrong an hour later. A risk manager wants
the opposite: a position they approve once, and a machine that cannot talk them into
anything outside it. Helm splits a stablecoin vault between a lending position and a
liquidity position, and puts the limit between the model and the money.

- **The model proposes.** A PyTorch network forecasts next-hour volatility and yield from
  real Base mainnet history and turns that into a split.
- **The contract disposes.** A Reactive contract on Reactive Lasna checks every proposal
  against the envelope the user signed, clamps it if it is out of range, refuses it if it
  is stale or from the wrong sender, and skips it if the trade is too small to be worth it.
- **The contract can act alone.** If the volatility the contract measures itself breaches
  the user's exit level, it pulls the vault to zero liquidity without asking the model
  anything. If the agent goes silent, the funds stay where they are — and the exit rule
  still works.

## AI proposes, contract enforces

This is the whole design, and it is worth reading twice because everything else in this
repository follows from it.

```
  market data            the model                 the contract              the money
  ───────────            ─────────                 ──────────              ─────────
  Base mainnet     ──►   MLP forecast      ──►    clamp to envelope   ──►   HelmVault
  swap history           (PyTorch)                  check freshness           (Base Sepolia)
  15-minute bars          │                         check sender              │
                          ▼                         check size                ▼
                     7102 bps LP               4000 bps LP               40% LP, 60% lending
                     (raw, unclamped)          (enforced, on-chain)      (position actually open)
```

The model is never told where the limits are. It posts what it thinks — 7102 basis points
of liquidity in the run below — and the contract answers with what the user agreed to.
The proposal is not a request that the contract may or may not honour; it is an input to a
function whose output the model cannot influence.

Three things follow, and all three are visible on-chain:

1. **The model can be wrong.** It is wrong most of the time. In the evaluation window its
   allocation was off by 41.13% of the vault on average. That is why the contract clamps.
2. **The model can be malicious.** The agent key can post proposals and nothing else. It
   holds no funds, it cannot call the vault's money functions, and every proposal it posts
   is checked against the envelope before it can move a cent.
3. **The model can be absent.** Turn the agent off and the vault holds its position. The
   volatility exit rule lives in the contract and keeps working — cycle 10 below is the
   contract pulling the vault to zero liquidity on its own, with no proposal in sight.

The envelope the user signs, in this deployment:

| Limit | Value | What it stops |
| --- | --- | --- |
| LP share | 0 – 4000 bps | more than 40% of the vault in liquidity |
| LP range width | 500 – 4000 bps | a position too narrow or too wide to be sensible |
| Cooldown | 20 s | two rebalances in the same breath |
| Volatility exit | 1200 bps | staying in liquidity through a volatility break |
| Minimum trade | 1000 bps | paying gas and price impact to move dust |
| Freshness window | 600 s | acting on a price the market has already left behind |

## The cycle log

The loop has six legs, and every one of them is a transaction a judge can open:

1. **Trigger** — the cron emitter ticks on Lasna; `HelmReactive` opens a cycle and asks the
   vault for a decision. *(Lasna)*
2. **Ask** — the Reactive callback proxy delivers that call to the vault on Base Sepolia;
   the vault reads its own position and emits `DecisionRequested`. *(Base Sepolia)*
3. **Proposal** — the agent answers with a raw split and posts `ProposalPosted`. The agent
   key cannot move funds. *(Base Sepolia)*
4. **Check** — the reactive contract reads the proposal, clamps it to the envelope, and
   emits `ProposalEvaluated` with the bits of the clamp it applied. *(Lasna)*
5. **Callback** — the contract asks the vault to act, through the callback proxy. *(Base Sepolia)*
6. **Result** — the vault moves the position and emits `Rebalanced`, or it does not move and
   the contract emits `NoTrade`. *(Base Sepolia)*

do. The contract says so explicitly with a `NoTrade` event rather than pretending to trade.

## The backtest

The claim is that forecasting beats reacting. That is a testable claim, so it was tested
against real history: the Uniswap v3 ETH/USDC pool on Base mainnet
(`0xd0b53D9277642d899DF5C87A3966A349A798F224`, 5 bps fee tier), 6694 bars of 15 minutes
covering 69.7 days. The network is fitted on the first 70% and scored on the last 30%,
which it never saw.

| Strategy | Total return | Max drawdown | Trades | Fees earned | Rebalance cost |
| --- | --- | --- | --- | --- | --- |
| **Helm (model + contract rules)** | **-4.26%** | -5.09% | 144 | $69.59 | $2,083.18 |
| Helm (model alone) | -4.91% | -6.06% | 126 | $91.68 | $1,077.16 |
| Best rate now | -19.18% | -20.14% | 303 | $182.67 | $13,825.23 |
| Static 50/50 | -5.68% | -8.06% | 0 | $129.02 | $0.00 |
| All lending | +0.16% | 0.00% | 0 | $0.00 | $0.00 |
| All LP | -11.52% | -16.01% | 0 | $258.03 | $0.00 |

**Helm beats "best rate now" by 14.91 points of total return.** That is the baseline the
brief names, and it is the one Helm is measured against: chasing the highest rate right now
is the thing people actually do, and it is expensive, because it trades 303 times and pays
$13,825 of costs to earn $55 more in fees than Helm does.

**Helm (model + contract rules)** is the deployed system: the model's allocation clipped to
the envelope the user signed, with the contract's own economic veto applied on top. The
model alone is shown next to it so the effect of that rule is visible rather than claimed —
on this window the veto is worth 0.64 points, and it was already deployed and already
firing on chain.

### The same model, window by window

One number for a twenty-day window says how Helm did in one market regime. The evaluation
region split into four consecutive, disjoint windows, scored with the same fitted model,
and every one of them out of sample:

| Window | Days | Price move | Helm | Best rate now | Static 50/50 | All lending | All LP |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 5.0 | -1.96% | -0.70% | -5.06% | -0.45% | +0.04% | -0.94% |
| 2 | 5.0 | -1.16% | -0.67% | -2.61% | -0.25% | +0.04% | -0.53% |
| 3 | 5.0 | -8.14% | -0.72% | -4.53% | -2.04% | +0.04% | -4.11% |
| 4 | 5.0 | -12.37% | -2.24% | -8.44% | -3.11% | +0.04% | -6.27% |

Helm beat `best rate now` in **4 of 4** windows, `all LP` in 3 and `static 50/50` in 2. It
beat `all lending` in **0 of 4**, and every one of these four windows was a falling one.

### Where Helm loses

**Helm loses to "all lending" by 4.43 points.** That is in this README, in the dashboard and
in the generated report, not in a footnote.

The reason is the window: the price fell 22.41% over the evaluation window, from $2,311.18
to $1,793.26. A full-range liquidity position is worth `sqrt(P1 / P0)` of what it was worth
when it was opened, so that move alone is a -11.91% drag on the liquidity leg. Helm earned
$69 of fees against a $2,083 bill for rebalancing. A strategy that holds no liquidity has
no impermanent loss to suffer, and in a market that only goes one way, holding nothing is
hard to beat.

So Helm does not claim to beat doing nothing. It claims three narrower things, and the
report is in [`docs/BENCHMARK.md`](docs/BENCHMARK.md):

- It beats the baseline real users actually use, `best rate now`, by 14.91 points, in 4 of
  4 windows.
- It beats holding the liquidity position outright (-11.52%) and a fixed half-and-half
  (-5.68%) on the same window, with the same costs.
- It does **not** beat staying in lending through a bear market. The contract is built to
  notice that and stop, and the veto is the mechanism: it compares the fee yield the chain
  measured itself against the lending rate the chain measured itself, and sends the
  allocation to zero when the edge is not there. On real market data it would have fired in
  64% of the window, and it is worth 0.64 points — it helps, and it is not enough.

One more thing the report is explicit about, because it is the kind of thing that is easy to
leave out: **the backtest does not simulate the volatility exit**, which is driven by
tick-level price observations that a fifteen-minute bar series does not reproduce, and
**the chain's fee estimator is measured swap by swap while the backtest measures it bar by
bar**. Both are named in `docs/BENCHMARK.md`, with what they would change.

Reproduce the whole thing with one command:

```bash
cd agent && python -m helm_agent.train --history data/base_eth_usdc_15m.jsonl --min-trade-bps 1000
```

It writes `agent/models/metrics.json`, and `scripts/claims.py` reads that file to produce
the table above.

## Architecture

```
                                 Reactive Lasna (5318007)            Base Sepolia (84532)
                                 ───────────────────────            ─────────────────────
  cron emitter ──every 1000──►   HelmReactive                         HelmVault
  blocks (~17 min)                ├─ opens a cycle                    ├─ holds the funds
                                  ├─ calls back ───────────────────►  ├─ reads its position
                                  ├─ reads the proposal ◄──────────   ├─ approves only the
                                  ├─ clamps to the envelope           │   lending pool and
                                  ├─ vetoes on its own fee edge       │   the LP pool
                                  ├─ exits on volatility              ├─ moves the position
                                  └─ grades the forecast              └─ emits Rebalanced
                                                                             ▲
                                                       the agent posts ──────┘
                                       ProposalPosted (raw split, no limits known)
```

**Reactive Lasna holds `HelmReactive`**, the enforcer. It subscribes to the cron emitter
and to the vault's `LimitsUpdated`, `ProposalPosted` and `Paused` events. On a trigger it
opens a cycle, requests a decision from the vault through the Reactive callback proxy, and
waits. When the proposal arrives it checks it — sender, cycle id, freshness, range, size,
the user's envelope, its own fee measurement, its own volatility measurement — and then
either asks the vault to move or explains why it did not.

**Base Sepolia holds `HelmVault`**, the only contract that holds or moves funds. It
accepts money-moving calls only from the Reactive callback proxy and from `HelmReactive`,
and only for a cycle id it has not spent. It pre-approves exactly two venues and nothing
else, so a compromised market contract cannot drain it.

**The agent** is a Python process. It listens for `DecisionRequested` on Base Sepolia,
loads the model, forecasts, posts `ProposalPosted`, and reconciles the verdict by reading
the reactive contract back. It holds no funds and it cannot call the vault's money
functions.

**The dashboard** is a Next.js app that reads both chains server-side, reads the agent's
ledger and the generated evidence file, and shows the split bar — the model's proposal
against the contract's answer — for every cycle. It has a machine-readable twin at
`GET /proof.json`.

The full design, down to the field shapes and the reason the Reactive network is the right
tool for this job, is in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

### Why Reactive, and not a cron job on a normal chain

Three things in this design need the Reactive network specifically:

- **The contract has to be woken by the chain and act without a transaction of its own.** A
  Reactive contract is called by the network when the event it subscribed to arrives, and
  the call is paid for in lREACT. A plain Solidity contract cannot watch anything.
- **The decision has to cross a chain boundary.** The model runs where it runs; the
  envelope and the money are on Base Sepolia; the trigger and the rules live on Lasna.
  The Reactive callback proxy is what makes the cross-chain call a single atomic step for
  the vault, with the reactive contract's address injected as the caller.
- **The rules have to run where nobody can edit them.** Once the envelope is on-chain, the
  check happens on-chain, and every decision is an event with a transaction hash. That is
  what turns "the AI respects your limits" into something a judge can read.

## Safety

The whole design assumes the model can be wrong, slow or compromised.

**The model cannot move money.** The agent key can post proposals and nothing else. It
holds no funds. The vault accepts calls only from the callback proxy and the enforcer.

**The envelope is the user's, and it cannot be widened by the model.** `setLimits` is
owner-only, the limits are mirrored onto the enforcer, and every proposal is clamped into
that range on-chain. The agent is never told where the limits are.

**The contract can de-risk without the model.** The volatility exit is measured on-chain
from the price path the contract observes itself. Above the user's exit level it pulls the
vault to zero liquidity — the only direction the contract may move on its own. Cycle 10 in
the table above is that rule firing.

**The contract can refuse to trade.** The economic veto compares the fee yield the chain
measured against the lending rate the chain measured. If liquidity provisioning does not
beat lending by the required margin, the vault is not put into liquidity at all. The
contract's own fee window starts at the first fee-paying swap, not at deployment, so an
unmeasured edge is treated as no edge.

**Stale, foreign and replayed proposals are refused.** A proposal from an address other
than the registered agent is rejected; a proposal for the wrong cycle is rejected; a
proposal older than the freshness window is rejected; a cycle id can only be spent once.

**The owner can stop everything.** The vault can be paused, which refuses every money-moving
call while the reactive contract keeps running. The owner can withdraw. The owner can
rotate the agent key.

**The LLM never decides an amount.** It writes the explanation shown next to a decision and
it can propose a limit envelope in plain English — but the envelope needs the user's
signature, and the allocation always comes from the neural network.

**What this does not do.** Helm runs on testnets: the lending pool and the liquidity
position are mocks, and no real money is involved. The code is unaudited. The model is
small and it loses to doing nothing in a falling market, as the backtest says plainly. The
market data in the demo is replayed from real Base mainnet history; everything after the
replayed market events — triggers, proposals, checks, callbacks, rebalances — is live on
testnet. The LLM explanation layer currently falls back to a deterministic template
because the paid endpoint's weekly allowance is exhausted, and the ledger says which
explanation it used.

## How to run it

### Read the evidence without running anything

```bash
git clone https://github.com/Alpha-Hackathon-Grinding-Society/helm.git
cd helm
cat docs/CLAIMS.md     # every number Helm makes, generated from the artifacts
cat docs/EVIDENCE.md   # every cycle, every transaction hash, read off both chains
```

### Check the live deployment

```bash
bash scripts/verify-deployment.sh
```

Twenty-six checks: the addresses have code on the right chain, the enforcer points at the
right vault, pools and agent, the vault's envelope and the enforcer's envelope agree, the
deployed runtime is the committed Foundry artifact byte for byte outside the immutable
addresses the constructor baked in, the vault can pay for its callbacks, the enforcer owes
the Reactive network nothing and has lREACT left, and the on-chain record holds the
evidence this README points at. It exits non-zero if any of that is untrue.

### Run the tests

```bash
cd contracts && forge test     # 37 tests — the reactive rules and the vault's money paths
cd agent && .venv/bin/python -m pytest tests   # 46 tests — the model and the decoding
```

### Run the backtest

```bash
cd agent
python -m helm_agent.data --days 45 --out data/base_eth_usdc_15m.jsonl \
    --pool 0xd0b53D9277642d899DF5C87A3966A349A798F224 --bucket 900
python -m helm_agent.train --history data/base_eth_usdc_15m.jsonl --min-trade-bps 1000
```

### Run the agent against a deployment

```bash
cd agent
export HELM_AGENT_PRIVATE_KEY=...      # the agent key: proposals only, no funds
export HELM_RPC_URL=https://base-sepolia-rpc.publicnode.com
python -m helm_agent.cli --no-sync
```

The agent polls for `DecisionRequested`, answers with a raw split and reconciles the
verdict by reading the reactive contract back. `--no-llm` uses the deterministic
explanation only; `--llm-timeout` bounds how long the paid explanation may take before
the template is used instead.

### Run the dashboard

```bash
cd dashboard
npm install
npm run dev        # http://localhost:3000
```

The dashboard reads the chains server-side and the committed ledger from the repository, so
it needs no database and no API keys. `GET /proof.json` returns the same evidence as JSON
for anything that wants to check it programmatically.

### Deploy it yourself

```bash
bash scripts/deploy.sh          # markets, enforcer, vault, wiring, limits, funding
bash scripts/setup-vault.sh     # fund the vault, the market maker and the callback reserve
bash scripts/topup-lreact.sh    # keep the enforcer's lREACT reserve alive
```

`scripts/deploy.sh` needs a funded Sepolia key in `deploy-keys/addresses.txt`; the lREACT
comes from the Reactive faucet at 100 lREACT per ETH.
